# v7.1 HOTFIX - Status Update

**Datum:** 2025-11-03  
**Version:** 7.1 → 8  
**Status:** ✅ FIX IMPLEMENTIERT

## 🎯 ROOT CAUSE

**Problem:** "Provided data is inadequate" auch im Incognito-Modus

**Ursache:** Dex Compound-Index `[team_id+ist_aktiv]` verursacht Probleme:
- `ist_aktiv` kann `true`, `false`, `1`, `0` sein
- Dexie hat Probleme mit Boolean-Werten in Compound-Indices
- Fehler tritt **immer** auf, nicht nur bei Alt-Daten!

## ✅ IMPLEMENTIERTE FIXES

### 1. Database Schema (v8)

```typescript
// ❌ ALT (v7) - PROBLEMATISCH
team_liga_participations: '++id, ..., [team_id+ist_aktiv]'

// ✅ NEU (v8) - HOTFIX
team_liga_participations: '++id, ..., ist_aktiv, [team_id+saison], [team_id+liga_id]'
//                                    ↑ Simple Index statt Compound
```

**Änderungen:**
- ❌ **Entfernt:** `[team_id+ist_aktiv]` Compound-Index
- ✅ **Behalten:** `ist_aktiv` als Simple-Index
- ✅ **Version:** 7 → 8 (Migration)

### 2. TeamService.getActiveParticipation()

```typescript
// ❌ ALT - verwendet Compound-Index
async getActiveParticipation(teamId: UUID) {
  return await db.team_liga_participations
    .where('[team_id+ist_aktiv]')
    .equals([teamId, true])
    .first();
}

// ✅ NEU - Simple Index + Filter
async getActiveParticipation(teamId: UUID) {
  const participations = await db.team_liga_participations
    .where('team_id')
    .equals(teamId)
    .toArray();
  
  return participations.find(p => p.ist_aktiv === true);
}
```

**Vorteile:**
- ✅ Funktioniert mit Boolean-Werten
- ✅ Kein Index-Problem mehr
- ✅ Minimal langsamere Performance, aber stabil
